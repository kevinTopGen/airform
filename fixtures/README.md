# Fixtures

Real inputs and outputs from the pipeline, so the frontend can be built and
styled before the API is finished. Every file here is generated by:

```bash
.venv/bin/python scripts/run_variants.py fixtures/input_front.jpg out
```

| File | What it is |
|---|---|
| `input_front.jpg` | A frontal photo, the kind `POST /simulate` accepts |
| `render_conservative.jpg` | Same face under "The Conservative" |
| `render_alar.jpg` | "The Base Reducer" — alar −9.5% |
| `render_dorsal.jpg` | "The Dorsal Preservationist" — bridge −15.7% |
| `render_tip.jpg` | "The Tip Sculptor" — tip −15.1%, shortened |
| `render_signature.jpg` | "The Miami Signature" — the most aggressive |
| `contact_sheet.jpg` | All five beside the original, cropped to the nose |
| `debug_landmarks.jpg` | Nose landmarks (yellow), fixed anchors (grey), nose frame |
| `report.json` | Measured params, each signature, and the resulting target |

`report.json` mirrors the shape `/simulate` returns, so it is the file to code
against. Note the two delta modes — width fields are fractions of *this*
patient's baseline, `nasal_length` is absolute in interpupillary distance:

```json
"pct_change": { "bridge_width": -16.3, "tip_width": -19.2,
                "alar_width": -10.7, "nasal_length": -5.0 }
```

## Notes for the frontend

**Renders are full-frame and identity-preserving.** The warp is geometric, so
the output is the same photograph with the nose moved — you can crossfade or
slider between input and render and nothing but the nose will shift. The
contact sheet is cropped to the nose because at full-frame the changes are a
few millimetres and read as subtle.

**A `strength` parameter scales any signature continuously**, which is what a
before/after slider should drive. `strength=0` returns the original,
`strength=1` the full signature; the same code path renders every frame in
between.

**Do not build a UI that implies all parameters are equally trustworthy.**
`alar_width` is measured reliably. `bridge_width` is advisory. `tip_width` is
currently not measurable at all — see the bake-off section of the root README.
The API reports per-parameter confidence and the UI needs to be able to show
"we could not measure this" rather than a number.

## Provenance

These are one consenting person — the project author — who chose to publish
their own photograph.

The repository contains **no patient photographs**, and must not. The surgeon
before/after images used to fit signatures are real patients' medical photos
from public Instagram accounts; those patients consented to their surgeon
posting them, not to redistribution in a public dataset. They stay in `work/`,
which is gitignored. Only the fitted signatures — numbers, no imagery — are
committed.
